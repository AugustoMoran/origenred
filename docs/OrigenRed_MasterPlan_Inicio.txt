1. Visión
OrigenRed es un marketplace argentino diseñado para conectar compradores con vendedoresindependientes mediante una experiencia moderna, intuitiva y confiable. La plataformaestá pensada para funcionar tanto como sitio web como aplicación móvil, compartiendola misma lógica de negocio y una identidad visual consistente.
2. Misión
Reducir la barrera de entrada para emprendedores permitiéndoles vender sin costosfijos, monetizando únicamente cuando concretan una venta.
3. Objetivos del producto
Marketplace nacional preparado para escalar.
Publicación gratuita de productos.
Comisión del 5% únicamente sobre el valor del producto.
Integración con Mercado Pago mediante vinculación de cuentas.
Experiencia premium pero extremadamente simple.
Escalabilidad desde el primer día.
Base técnica preparada para millones de publicaciones.
4. Principios de diseño
El usuario nunca debe sentirse perdido.
Todas las acciones importantes deben requerir pocos pasos.
La confianza debe estar visible en cada pantalla.
El rendimiento es una prioridad.
La versión móvil tiene la misma importancia que la web.
Cada módulo debe ser independiente dentro del monolito modular.
5. Modelo de negocio
Compradores y vendedores utilizan la plataforma sin costo de acceso.Cada vendedor dispone de hasta 100 publicaciones activas. Cuando una venta se concreta,Mercado Pago distribuye automáticamente el dinero: 95% para el vendedor y 5% paraOrigenRed. El envío no forma parte de la base de cálculo de la comisión.
6. Servicios complementarios
OrigenRed ofrecerá opcionalmente servicios profesionales para los vendedores:desarrollo de páginas web, posicionamiento SEO, Google Search Console, Google Analytics,Meta Ads y otras soluciones de marketing digital. Estos servicios constituyen una líneade negocio independiente del marketplace.
7. Roles
Administrador
Control absoluto de la plataforma, aprobación de vendedores, moderación, configuración global, atención de reclamos, gestión de servicios y métricas.
Vendedor
Publicación de productos, administración de stock, ventas, envíos y atención postventa.
Comprador
Compra con o sin cuenta, favoritos, historial, chat post compra y reclamos.
8. Reglas fundamentales
Todos los vendedores son aprobados manualmente.
No existen tiendas completas gratuitas dentro del marketplace.
El chat entre comprador y vendedor solo se habilita después de la compra.
Las redes sociales del vendedor no se muestran antes de comprar.
Los productos denunciados llegan inmediatamente al administrador.
El vendedor es responsable de devoluciones, garantías y datos logísticos.
El cálculo de envío se realiza antes del pago utilizando código postal.

Capítulo 1 — Filosofía del Diseño
OrigenRed no pretende ser simplemente un ecommerce.
El objetivo es construir un ecosistema donde cualquier emprendedor pueda comenzar a vender desde el primer día sin tener conocimientos técnicos.
Toda la experiencia debe transmitir cuatro sensaciones:
confianza 
rapidez 
simplicidad 
profesionalismo 
La plataforma debe sentirse moderna pero sin sobrecargar visualmente al usuario.
Nunca debe existir una pantalla donde el usuario no sepa qué hacer.
Cada acción importante debe requerir la menor cantidad posible de pasos.
Si Mercado Libre puede realizar una acción en cinco pasos, OrigenRed debería intentar resolverla en tres.

Principios de UX
Toda la aplicación respetará los siguientes principios.
1. Claridad
Siempre debe existir una acción principal claramente visible.
Ejemplo:

Agregar a favoritos

Aunque una acción tarde algunos segundos:

Capítulo 7 — Carrito de Compras (Introducción)
El carrito será uno de los módulos más complejos porque OrigenRed permite comprar productos de distintos vendedores en una sola operación.
Cada vendedor mantiene:
su stock. 
su envío. 
su logística. 
su responsabilidad. 
Pero para el comprador la experiencia debe sentirse como una única compra, aunque internamente el sistema la divida en múltiples pedidos.

Quiero definir el flujo correctamente.
El frontend solicita una URL firmada.

Nunca pasar archivos pesados por Express.

Idempotencia
Esto es algo que quiero dejar definido desde el inicio.
Los webhooks de Mercado Pago y otros proveedores pueden llegar repetidos.
Por eso toda operación crítica debe ser idempotente.
Ejemplo.
Si llega dos veces el mismo payment.approved, el sistema debe detectar que ya fue procesado y no descontar stock dos veces ni generar dos chats.

Cada request recibirá un identificador único.
Ese ID viajará por:

eventos, 
workers, 
webhooks. 
Así, cuando haya un problema, podrás reconstruir todo el recorrido de una operación.

Capítulo 11 — Principios Fundamentales de OrigenRed

Filosofía General
OrigenRed no nace para ser "otro marketplace".
Nace para convertirse en el ecosistema digital donde cualquier emprendedor argentino pueda comenzar a vender sin inversión inicial y, si su negocio crece, encontrar dentro de la misma plataforma todas las herramientas necesarias para seguir creciendo.
El éxito de OrigenRed no dependerá únicamente de la tecnología.
Dependerá de la confianza.
Si los vendedores confían en la plataforma, publicarán más.
Si los compradores confían en la plataforma, comprarán más.
Todo el diseño del sistema gira alrededor de ese principio.

Los 10 principios de OrigenRed
1. Simplicidad
Todo debe ser fácil de entender.
Si una función necesita un tutorial para usarse, probablemente esté mal diseñada.

2. Rapidez
La plataforma debe sentirse instantánea.
Cada segundo de espera reduce ventas.

3. Transparencia
Las reglas deben ser claras.
Comisión visible. 
Costos visibles. 
Estado del pedido visible. 
Estado del envío visible. 
Estado del pago visible. 
Nunca generar incertidumbre.

4. Escalabilidad
Nada debe desarrollarse pensando únicamente en el presente.
Cada módulo debe soportar un crecimiento de cientos de veces sin requerir una reescritura completa.

5. Modularidad
Cada funcionalidad debe poder evolucionar independientemente.

6. Seguridad
Toda decisión debe favorecer la protección de:
usuarios, 
vendedores, 
pagos, 
datos. 

7. Automatización
Todo proceso repetitivo deberá automatizarse siempre que no reduzca el control administrativo.

8. Experiencia de Usuario
La interfaz debe acompañar al usuario.
Nunca complicarlo.

9. Datos
Toda decisión importante debe basarse en información medible.

10. Comunidad
OrigenRed debe ayudar al crecimiento de los emprendedores.
Si ellos crecen, la plataforma también crece.

Reglas Inquebrantables del Proyecto

Filosofía
Toda decisión que se tome en el futuro deberá respetar estas reglas.
No importa quién programe OrigenRed dentro de cinco años.
No importa cuántos desarrolladores trabajen en el proyecto.
Estas reglas no deberían romperse nunca.

Regla 1
El usuario siempre primero.
Si una decisión técnica perjudica la experiencia del usuario, debe buscarse otra solución.
La tecnología existe para servir al negocio y a las personas, no al revés.
Regla 3
Todo debe poder escalar.
No desarrollar pensando en cien usuarios.
Pensar siempre en millones.
Aunque inicialmente solo existan unos pocos.

Regla 4
Ningún módulo puede depender completamente de otro.
Cada parte del sistema debe poder evolucionar sin obligar a reescribir el resto.

Regla 5
Automatizar siempre que sea posible.
Pero sin quitarle control al administrador.
OrigenRed debe trabajar para vos.
No al revés.

Regla 6
Nunca perder información.
Toda acción importante debe quedar registrada.
Ventas.
Pagos.
Cambios.
Moderaciones.
Mensajes.
Logs.
Auditorías.
Nada importante debe desaparecer.

Regla 7
Performance antes que cantidad de funciones.
Una plataforma rápida vende más.
Una plataforma lenta pierde usuarios.
Cada nueva función deberá analizar su impacto sobre el rendimiento.

Regla 8
Consistencia absoluta.
Un mismo botón debe verse igual en toda la plataforma.
Los colores.
Las tipografías.
Los formularios.
Los mensajes.
Todo debe respetar el Design System.

Regla 9
El vendedor nunca debe sentirse abandonado.
Siempre deberá saber:
qué vendió, 
cuánto cobró, 
cuándo cobrará, 
dónde está el pedido, 
qué debe hacer. 

Regla 10
El comprador nunca debe sentir incertidumbre.
Siempre deberá saber:
dónde está su pedido, 
quién lo vende, 
cuándo llegará, 
cómo reclamar, 
cómo contactarse. 

Regla 11
OrigenRed no compite con sus vendedores.
OrigenRed crece cuando ellos crecen.
El marketplace existe para potenciar negocios.
No para reemplazarlos.

Regla 12
Los servicios complementan el marketplace.
El desarrollo web.
Meta Ads.
Google Ads.
SEO.
Analytics.
Hosting.
Dominios.
Todo eso existe para ayudar a los vendedores a profesionalizarse.
Nunca será obligatorio.

Regla 13
Los datos pertenecen a quien los genera.
Cada vendedor podrá acceder únicamente a su propia información.
Nunca a la de otros vendedores.
La privacidad es un pilar del sistema.

Regla 14
Seguridad por defecto.
Todo nuevo módulo deberá nacer seguro.
No se agregará seguridad después.

Regla 15
El administrador siempre tiene el control final.
Podrá:
aprobar vendedores, 
suspender cuentas, 
intervenir disputas, 
modificar configuraciones globales, 
cambiar comisiones, 
moderar publicaciones, 
enviar comunicaciones, 
activar o desactivar funcionalidades. 
Sin necesidad de modificar el código.

Plataforma Multiplataforma (Requisito Obligatorio)
OrigenRed no es únicamente una aplicación web.
Desde su primera versión deberá ser una plataforma multiplataforma compuesta por:
Aplicación Web. 
Aplicación Android. 
Aplicación iOS. 
Progressive Web App (PWA). 
Los tres clientes deberán compartir la misma lógica de negocio a través de una única API desarrollada en Node.js + Express.
La experiencia de usuario deberá mantenerse consistente entre todas las plataformas, respetando el mismo Design System, componentes y flujos.
La aplicación móvil se desarrollará con React Native + Expo, permitiendo compilar tanto para Android como para iOS a partir de una única base de código.
La aplicación web se desarrollará con React + Vite + TypeScript.
Todas las nuevas funcionalidades implementadas deberán evaluarse simultáneamente para:
Web. 
Android. 
iPhone. 
No se aceptarán funcionalidades exclusivas para una plataforma, salvo que exista una limitación técnica documentada.
